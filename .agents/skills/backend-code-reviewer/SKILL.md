### 目标 (Objective)

对后端代码进行详细的审查，确保代码质量、规范性和最佳实践的遵循。本项目后端使用 Go + Gin 框架，数据库支持 SQLite/MySQL/PostgreSQL。

### 审查要点 (Review Points)

- **错误处理**：error 是否被正确处理和传播？是否有被忽略的 error 返回值？
- **并发安全**：goroutine 是否有泄漏风险？共享变量是否正确加锁？是否存在竞态条件？
- **SQL 安全**：是否使用参数化查询防止 SQL 注入？动态拼接 SQL 是否安全？
- **API 设计**：REST 端点是否遵循项目现有风格？请求/响应结构是否合理？
- **中间件**：权限校验、限流、日志是否通过中间件正确应用？
- **数据库**：查询是否高效？是否有 N+1 问题？索引使用是否合理？
- **资源管理**：HTTP 请求 body、文件句柄、数据库连接是否被正确关闭？
- **配置管理**：敏感信息（密钥、密码）是否从环境变量/配置文件读取，未硬编码？
- **日志规范**：是否使用项目统一的日志方式？敏感数据是否被泄露到日志中？
- **输入校验**：用户输入是否在进入业务逻辑前完成校验？
- **依赖管理**：新增依赖是否必要？go.mod 是否整洁？

### 代码审查反馈 (Review Feedback)

按优先级提供反馈：

1. **重大问题**（必须解决）：安全漏洞、数据损坏风险、goroutine 泄漏、错误被忽略
2. **提示事项**（应解决）：性能问题、代码结构不合理、缺乏输入校验
3. **建议**（考虑改进）：命名优化、代码简化、注释补充

每个问题应附带具体的代码位置和修改建议。

### 重构策略 (Refactoring Strategy)

- **提取公共逻辑**：将 controller/service 中的重复代码抽成函数或 helper
- **简化复杂函数**：长函数按职责拆分，遵循单一职责原则
- **优化数据库查询**：减少不必要的查询、合并批量操作、添加合适的索引
- **增强可测试性**：将依赖抽象为接口，方便单元测试 mock
- **减少指针传递风险**：明确 nil 处理，避免不必要的指针嵌套
